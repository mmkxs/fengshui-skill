# 分析依据与自动/人工分工

原则：**通过数据能分析出来的自己分析，不能则让用户提供。**

空间智能分析（物品识别、房间几何、层高、门窗）能给出的，直接用于规则计算，不再追问用户；识别无法确定或数据里根本没有的（朝向、入户门角色、门窗开合、真实风量、物品身份确认），直接向用户提问，答复作为补充标注回填。

## 各依据的来源与分工

| 依据 | 数据可得（自动分析） | 需用户提供 / 确认 |
| --- | --- | --- |
| 物品摆放 | bed/desk/sofa 几何盒与审查点（物品识别） | 物品身份：检测到的是不是床 / 桌 / 沙发 |
| 门洞朝向 | 门开口平面（门识别） | 哪一扇是入户门、开向 |
| 镜面 | 镜面有限平面（物品识别） | 反射面正反 |
| 梁体 | 梁体几何盒（识别 / 标注） | — |
| 墙体遮挡 | 墙 / 隔断几何盒（墙识别） | — |
| 层高 | 房间净层高（空间解析） | — |
| 开口通风 | 门窗位置与开口尺寸 | 开合状态、对流通风、真实风量 |
| 坐向 | — | 坐向度数、参考北、测量误差 |

分析输出 `evidence.basis` 逐项给出 `status`（supplied / missing / not_applicable / pending）与 `questions`（缺失时需向用户提出的具体问题）。工作流按 `consultation.questions`（同时写入 evidence.questions）合并同类问题后问用户并等待回复，答复回填为标注后重跑；有未完成问答时暂停 HTML 生成，不在交付报告中罗列缺项。不得用默认值静默补缺，也不把检测标签当已确认身份。
